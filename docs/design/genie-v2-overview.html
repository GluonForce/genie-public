Genie v2 Overview

Speak an idea, get a working web prototype. A member of the public signs up with their email and describes the app they want out loud. Genie turns the recording into requirements, which the user approves. One of two admins reviews the request, the builder agent from internal Genie builds a Next.js prototype, an admin checks it, and the user gets a link by email.

How a prototype gets made

Who acts at each step. The user only sees the steps in their own lane plus a "Building" status in between.

UserAdminSystem
  1. Signs up with emailClerk, email verified. IP recorded.
  2. Records the ideaUp to 10 min. Can play back and re-record freely.
  3. Transcribes and writes requirementsOpenRouter: speech-to-text, then the requirement agent.
  4. Reviews the summaryUp to 2 remarks to regenerate. Recording is now locked.
  5. Approves, or declinesDeclining warns that the free prototype is used up and asks why.
  6. Accepts or rejects the requirementsSees audio, transcript, versions, IP flag. Cannot edit.
  7. Builds and deploys a previewRailway worker runs the builder agent in an E2B sandbox, exports a static site to Cloudflare.
  8. Checks the built prototypeRelease, rebuild with a defect note, or decline.
  9. Emails the linkSent to the sign-up email. Anyone with the link can open it.
  10. Expires the link after 3 daysFiles are kept so a later redeploy needs no rebuild.
Admin declines at review or QA → user gets an email with the reason. The free prototype is used up. Build fails → one automatic retry, then admins are emailed and can retry. The user still sees "Building".

Business rules

Quota and accounts

  • BR-1One prototype per email, enforced by the database.
  • BR-2Gmail dot and plus variants count as the same email. Disposable domains are refused.
  • BR-3Deleting the account and signing up again does not reset the quota.
  • BR-7IP is tracked. A shared IP flags the request for the admin; it never blocks.

Recording and requirements

  • BR-8Recording runs 15 seconds to 10 minutes.
  • BR-5Play back and re-record freely until Generate. Then the recording is locked.
  • BR-4At most 2 remarks to regenerate the requirements.
  • BR-6After that, approve or decline. Declining uses up the free prototype.

Review and delivery

  • BR-9Nothing is built without an admin approving it.
  • BR-14Admins accept or reject requirements as the user approved them, never edit them.
  • BR-11The user sees nothing until an admin has checked the build and released it.
  • BR-12Released links stay live for 3 days, then expire.
  • BR-13No cost cap per build in Phase 1. Cost is recorded per build.

What a prototype may contain

  • BuildFrontend only: Next.js, data kept in the browser's localStorage, a mocked backend.
  • BuildNo real backend, database, auth or calls to outside services. Same strict rules as internal Genie.
  • BuildMust pass lint, type check and a static export build.
  • HostServed from its own subdomain on a separate domain, with outside network calls blocked.

Data and permissions

Three tables

usersWho someone is. The normalised email is the quota key; the role is a copy of Clerk's.
prototypesWhere each prototype stands now: status, transcript, requirements, decision, build, link, expiry.
eventsEverything that happened: who, in which role, what, when, from which IP.

Full columns and the event list are in the Genie v2 Data Model page.

Who can do what

ActionUserAdmin
Record, remark, approve or decline own requestOwnNo
Review queue, audio, transcript, IP flagsNoYes
Accept or reject requirementsNoYes
Release, rebuild, take offlineNoYes

Clerk decides the role. Routes check it, and the database backs up the limits.

Delivery plan

  1. M0

    Foundations

    Repo, Clerk roles, Supabase schema, Resend, domains.

  2. M1

    Builder in the cloud

    Agent in E2B, static export, R2 and Cloudflare Worker, end to end from fixed requirements.

    Riskiest part, do first
  3. M2

    Capture

    Recorder, transcription, requirement agent, remarks, approve or decline, quota and IP rules.

  4. M3

    Admin panel

    Queue, review, build view, preview and QA release, retry, takedown, event timeline.

  5. M4

    Hardening

    Emails, 3-day expiry, rate limits, monitoring, privacy terms, test run of about 20 builds.
